# Application tables live in a private schema; Supabase's Data API never sees them

Supabase automatically publishes every table in the `public` schema through its REST and GraphQL Data API, reachable with the publishable key that every browser has. Docent instead keeps all application tables in an `app` schema that the Data API does not expose, so the only way to read or change Docent data is through the Docent API, where permissions are enforced inside each query (PRD › Answers have to be grounded). Row level security is also enabled on every table, with no policies, so even a future configuration change that exposed the schema would return nothing. The alternative — tables in `public` protected by RLS policies — would put permission rules in two places (SQL policies and API queries) and make one misconfigured policy a data leak. The cost: Supabase's client libraries can't query Docent data directly from the browser, which Docent doesn't do anyway.
